# global-core-origins-v1

The first global card-program pack under ADR-0004. Status: **selected, pending
physical verification; inventory drafted; no executable programs.**

| File | What it is | Written by |
| --- | --- | --- |
| `selection.json` | Which decks and why, with the capability batches R3-A0..A3 | Codex, `r3-pack-selection.v1` |
| `inventory.draft.json` | R3-A0 output: every selected card split into stable clauses, labelled, as a `card-behavior-manifest.v1` with `status: draft` | generated by `build_r3_inventory.py` |
| `inventory_ledger.json` | Per card: which printing was read, whether errata applies, whether the snapshot still carries pre-errata text, the mechanics each clause needs, and which batch unblocks it | generated alongside |
| `INVENTORY.md` | The same ledger as prose, per deck and per mechanic — the view R3-A1 rulings read | generated alongside |

## What the inventory can and cannot say

The behavior-manifest validator requires a tested program for any clause
labelled `full` or `partial`. R3-A0 builds no programs, by rule. So every
clause in `inventory.draft.json` is `unsupported` — with its missing mechanics
named explicitly — or `stale`, where the bundled card text still carries
pre-errata wording. The `full`/`partial` labels the batch asks for are drafted
as **recommendations** in the ledger, never written into the manifest where
they would mean something that has not happened.

`current_text_hash` is computed by the same catalog Deck Coach uses, with the
same errata applied, so a future active manifest and today's draft agree on
what "current text" means.

Nothing here activates. `status` is `draft`, no `program_id` is set, and the
gate fails if either changes without the programs and tests that justify it.
