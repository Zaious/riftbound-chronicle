# Riftbound Library

This library holds two independent books: **deckbuilding** (what to put in a deck, before the game starts) and **gameplay** (what to do with it, turn by turn, once the game is live). They are different skills that happen to share one game — a question about mulligan strategy is not a question about rune ratios, and blending them into one undifferentiated wall of advice makes both worse. Route to the one that fits, read it whole, then answer.

## Picking a book

1. `ls references/` first — the book list is whatever's actually on disk, not a hardcoded list here. A written-out list in this file would be a second copy of the truth, and it would drift the moment a book is added or renamed.
2. A book lives at `references/<book>/<book>.md`. **Read the whole book before answering** — each one is designed as a self-contained routing table + methodology package, not a grab-bag of independent tips you can sample from.
3. Deckbuilding questions ("can I build X", "is this card/deck legal", "how should I split my runes", "write a theme-deck guide", "does this classic decklist still work after the ban update") → `deckbuilding` book.
4. Gameplay questions ("what happens if I play this into that", "should I pass priority here", "do I attack this battlefield or wait", "how do I mulligan this hand", "did I misplay that combat") → `gameplay` book.

## Route, don't snapshot — the one rule that governs both books

Riftbound's rules text and legal card pool are a live, Riot-maintained thing, not a fact this file already knows for all time. The official Rules Hub —

**https://playriftbound.com/en-us/rules-hub/**

— hosts the Core Rules PDF, the Tournament Rules PDF, the current ban lists (Constructed and 2v2 separately), and card errata, and Riot edits it directly when something changes (most recently the ban list moved 2026-07-24). That domain used to be `riftbound.leagueoflegends.com`; it now 301-redirects to `playriftbound.com` — if a citation or bookmark still points at the old host, follow the redirect rather than trusting a possibly-stale mirror.

- **Base rules** — turn phases, how the chain resolves, how combat is scored — are stable mechanics, not a moving target, so the books below summarize them directly and cite where they came from.
- **Card data and the ban list should be read from a local file first, not fetched per question.** Whatever this deployment bundles or has access to as a local card/ban database — check for a `data/` folder alongside this library, or a private companion skill folder (commonly named with a `-private` suffix) that binds specific local paths — is already as current as it was last updated, and reading it is a local file read, not a web request. Read it fresh each time rather than trusting an answer from earlier in the conversation, but there is no reason to hit the network for a routine "what does this card do" question when a local answer already exists. This library's own bundled default (no private companion needed) is `data/riftcodex_cards_raw.json` — full official English rules text for every card across every set, sourced from api.riftcodex.com (see that folder's own `README.md` for provenance and known gaps, e.g. no Set 5/Radiance yet as of the last harvest). It has no ban-status field — bans are a separate, Riot-official axis, always cross-check the live Rules Hub or a private companion's ban-list binding for that.
- **A live web fetch to the official Rules Hub is the rare escalation path, not the default one.** Reach for it only when there's a specific reason to doubt the local data is current — e.g. a user mentions a ban update that isn't reflected locally yet, or enough time has passed since this book's `last-verified` date that a set/ban change is plausible. Don't fetch per card question; that's wasted latency for no accuracy gain when local data already has the answer.
- **Don't invent official wording that isn't actually available.** If verbatim official card text is needed in a language or form the local data doesn't have, say so plainly rather than translating/paraphrasing something else and presenting it as the official printed wording — then fetch a source that mirrors the actual print, or defer.
- **The same discipline that governs the deckbuilding book's card-pool sections applies whenever any book names a specific card or archetype**: a claim sourced from before Riftbound's first ban wave (2026-03-31) may describe something already banned everywhere, including in a region that hasn't even launched yet — see the deckbuilding book's `regional-legality-model.md` "compound gap" section for why. This is a library-wide rule, not a deckbuilding-only one; the gameplay book currently stays at the card-agnostic mechanics level specifically to avoid this exposure.
- Community sites — riftbound.gg, learnriftbound.gg, riftbound.zone, runesandrift.com, riftmana.com, app.riftjudge.com (a community-run rulings/FAQ database, useful for edge-case interaction questions) — are good for explanation and worked examples, but none of them are Riot. Cite them as community analysis, and defer to the official PDFs whenever the two disagree.

## Public library, private companion

Everything in this folder (`SKILL.md` and everything under `references/`) is written to be portable — no private repo paths, no one deployment's internal function/file names. That's deliberate: this folder's real canonical location is a separate, independent public repo, and any private repo that uses it reaches it via a local mirror (a directory junction on that machine, not a copy) rather than owning its own duplicate — edit the content once, it's correct everywhere it's used, nothing to keep in sync by hand.

The trade a private deployment makes for that portability: this folder can never name a specific repo's actual file paths, function names, or local database locations, even though real answers sometimes need them. The fix is a **sibling folder, not a mirrored one** — conventionally named with a `-private` suffix (e.g. `riftbound-private`, sitting next to this `riftbound` folder, never inside it) — that exists only in a given private deployment, is never part of what's mirrored publicly, and holds exactly the bindings this book intentionally left generic: which local file has the card database, which has the ban list, how a specific site's content-authoring conventions work. If such a folder exists alongside this one, read it whenever this book says "a private companion, if one exists" or "your local database." If it doesn't exist, there's no private deployment here — the generic instructions in this book are all there is, and that's fine for a project working directly off the datasets this library itself ships with.
