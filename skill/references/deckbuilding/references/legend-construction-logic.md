# Legend construction logic (catalog index)

This file exists because the method demonstrated on Kai'Sa and Annie in the main deckbuilding book scales cleanly to the full roster -- the derivation is grounded in permanent card text and the game's own already-established archetype framework, not a community-guide snapshot, so it doesn't carry the staleness risk that would come from writing up 46 entries' worth of "what people currently play." Read the main book's methodology section first; this index plus the `legends/` files are the reference table it produces when run across the whole current roster, not a substitute for understanding the method itself.

**Every entry is a Tier 1 hypothesis, not a Tier 2-confirmed fact, unless the Status column says otherwise.** Every catalog entry checked against real established play so far has required a correction -- 3 for 3 (Darius, Master Yi, Viktor; see `references/verification-log.md`). Kai'Sa, one of the main book's two worked examples and not a row in this catalog, makes it 4 of 5 across the full verification log once she's included. Not a rare edge case either way. Specifically: (1) an entry's named archetype (aggro/control/combo) is this book's own framework, not guaranteed to match how the community actually talks about that Legend -- Darius and Kai'Sa's real-play labels don't fit the three-way split cleanly. (2) Any entry describing "the two Champions split into different lanes" is unverified by construction -- Tier 1 cannot tell a real fork from an apparent one, because that often depends on synergy with cards outside the Legend+Champion kit; Master Yi, Viktor, and Kai'Sa all read as forks on paper and were not, in practice. Treat every split-labeled entry below with that caveat until it's been through the verification log -- don't quote one as settled.

## How to use this table

1. **Looking up one Legend you already know the name of** -- find its row, open the linked file in `legends/`. That file has the full derivation; this row is only a summary.
2. **Looking for a counter-matchup, comparable archetype, or "which other Legend does something like this"** -- scan the Archetype and Mechanic tags columns first. They're deliberately kept as short, grep-able keywords for exactly this cross-referencing use case, so you don't have to open all 46 files to find candidates. Only open the specific files that look like real matches.
3. **Status** -- `Tier 1` (default, unverified hypothesis), `Tier 2 ✓` (confirmed or corrected against real play, see the linked file's callout and `verification-log.md`), or `Tier 1 (data caveat)` (Kennen only -- see note below).

## Notes

- **Kai'Sa and Annie** are not rows here -- they're the main deckbuilding book's canonical worked examples for the method itself, and duplicating them here would drift from that copy. Both are Tier 2-confirmed; see `references/deckbuilding.md` directly.
- **Kennen** carries a data caveat: the source packet paired it with several champion cards that turned out to be unrelated Legends' cards (a data artifact `skill/scripts/extract_legend_packets.py` now filters out for every Legend generated after this entry was written). Treat Kennen as lower-confidence than the rest of this catalog until it's regenerated from the fixed script and re-verified.
- **5 of 46 entries have not been Tier 2-verified** (41 done: Darius, Viktor, Master Yi, Teemo, Volibear, Yasuo, Zed, Azir, Jhin, Pyke, Renekton, Rumble, Jinx, Lux, Vi, Diana, Ahri, Akali, Draven, Ezreal, Ivern, Jax, Jayce, Kennen, Ambessa, Fiora, Garen, Irelia, Kha'Zix, LeBlanc, Lee Sin, Leona, Lillia, Lucian, Mel, Miss Fortune, Nasus, Ornn, Poppy, Rek'Sai, Renata Glasc). Most checked entries have needed at least one correction, but not all -- Ivern, Jayce, Leona, and Nasus came back fully **CONFIRMED**, evidence Tier 1 is not reliably wrong, just not reliably right either, which is exactly why every entry still needs the check rather than being assumed either way. Where corrections were needed, the error keeps showing up in different shapes: an implicit "default Champion" assumption backwards (Jinx, Vi, Ezreal), a real-but-lopsided split leaning the wrong way (Draven, Lucian's Gunslinger, Lillia's Protector of Dreams, Poppy's Defender of the Meek, Rek'Sai's Swarm Queen), an archetype label wrong even with the mechanics right (Jax: control vs. midrange; Kha'Zix: control/attrition vs. real tempo/midrange; Lillia: combo-leaning vs. real aggro; Poppy: control vs. real midrange; Rek'Sai: aggro flatly denied by name in real coverage in favor of off-tempo/midrange), a Core-unfolding narrative that doesn't match any real competitive build (Kennen), an analysis that omitted a real third Champion print entirely (Fiora), a "genuine partnership" where one side is essentially unplayed and the real win-condition framing is inverted (Irelia: combo read vs. real tempo/control; Lee Sin's Ascetic, real only pre-Spiritforged), a win-condition claim stated as flatly false that real coverage directly inverts (LeBlanc: "not a card-advantage engine" vs. a real card-draw combo engine built on an off-kit card), sources disagreeing with each other on the label even when the mechanic itself is confirmed (Mel: control vs. midrange; Renata Glasc: control vs. control/combo), a "central engine card" claim inverted by real deckbuilding (Ornn: Blacksmith, read as the clearest control signal in the text, is reportedly cut from competitive builds entirely, while Forge God is the real default and the real label is Voltron/combo-engine-midrange, not control), and -- most seriously -- a textually-accurate derivation describing a shell current top play doesn't build at all (Lux, Yasuo, Garen, and Miss Fortune's real Dazzling Aurora ramp deck vs. a derived open-battlefield token-swarm). Treat every unchecked entry's archetype call, "default Champion" assumption, and any "splits by Champion" claim as a working hypothesis, not a settled answer -- say so if asked about one before it's been through `verification-log.md`.
