# Legend construction logic (catalog index)

This file exists because the method demonstrated on Kai'Sa and Annie in the main deckbuilding book scales cleanly to the full roster -- the derivation is grounded in permanent card text and the game's own already-established archetype framework, not a community-guide snapshot, so it doesn't carry the staleness risk that would come from writing up 46 entries' worth of "what people currently play." Read the main book's methodology section first; this index plus the `legends/` files are the reference table it produces when run across the whole current roster, not a substitute for understanding the method itself.

**As of 2026-08-18, all 46 entries below have been through Tier 2 verification against real, cited sources** -- see `references/verification-log.md` for the full log. Only 4 came back fully CONFIRMED (Ivern, Jayce, Leona, Nasus); the rest needed at least one correction, most commonly a real "default Champion" that isn't the one an entry emphasized, an archetype label that doesn't match current real-play language, or (in several of the most serious cases) a real competitive archetype built substantially or entirely from cards outside the analyzed Legend+Champion kit. The Status column below still records each entry's individual verdict (CONFIRMED / partially confirmed / not confirmed) -- treat every "not confirmed" or "partially confirmed" row's specific claims as corrected in the row itself and in the linked `legends/` file, not as still-open. Specifically, two patterns recurred often enough to be worth naming up front: (1) an entry's named archetype (aggro/control/combo) is this book's own framework, not guaranteed to match how the community actually talks about that Legend. (2) Any entry describing "the two Champions split into different lanes" needs its own verification -- Tier 1 cannot tell a real fork from an apparent one by construction, because that often depends on synergy with cards outside the Legend+Champion kit; the large majority of split claims checked here turned out to not be genuine, even-weighted forks in practice.

## How to use this table

1. **Looking up one Legend you already know the name of** -- find its row, open the linked file in `legends/`. That file has the full derivation; this row is only a summary.
2. **Looking for a counter-matchup, comparable archetype, or "which other Legend does something like this"** -- scan the Archetype and Mechanic tags columns first. They're deliberately kept as short, grep-able keywords for exactly this cross-referencing use case, so you don't have to open all 46 files to find candidates. Only open the specific files that look like real matches.
3. **Status** -- `Tier 1` (default, unverified hypothesis), `Tier 2 ✓` (confirmed or corrected against real play, see the linked file's callout and `verification-log.md`), or `Tier 1 (data caveat)` (Kennen only -- see note below).

## Notes

- **Kai'Sa and Annie** are not rows here -- they're the main deckbuilding book's canonical worked examples for the method itself, and duplicating them here would drift from that copy. Both are Tier 2-confirmed; see `references/deckbuilding.md` directly.
- **Kennen** carries a data caveat: the source packet paired it with several champion cards that turned out to be unrelated Legends' cards (a data artifact `skill/scripts/extract_legend_packets.py` now filters out for every Legend generated after this entry was written). Treat Kennen as lower-confidence than the rest of this catalog until it's regenerated from the fixed script and re-verified.
- **All 46 entries have been Tier 2-verified as of 2026-08-18** (Darius, Viktor, Master Yi, Teemo, Volibear, Yasuo, Zed, Azir, Jhin, Pyke, Renekton, Rumble, Jinx, Lux, Vi, Diana, Ahri, Akali, Draven, Ezreal, Ivern, Jax, Jayce, Kennen, Ambessa, Fiora, Garen, Irelia, Kha'Zix, LeBlanc, Lee Sin, Leona, Lillia, Lucian, Mel, Miss Fortune, Nasus, Ornn, Poppy, Rek'Sai, Renata Glasc, Rengar, Sett, Shen, Sivir, Vex). Only 4 came back fully **CONFIRMED** (Ivern, Jayce, Leona, Nasus) -- evidence Tier 1 is not reliably wrong, just not reliably right either, which is exactly why every entry needed the check rather than being assumed either way. Where corrections were needed, the error kept showing up in recurring shapes: an implicit "default Champion" assumption backwards (Jinx, Vi, Ezreal, Rengar), a real-but-lopsided split leaning the wrong way (Draven, Lucian's Gunslinger, Lillia's Protector of Dreams, Poppy's Defender of the Meek, Rek'Sai's Swarm Queen), an archetype label wrong even with the mechanics right (Jax, Kha'Zix, Lillia, Poppy, Rek'Sai, Sivir), a label accurate for an earlier meta but stale for the current one (Sett), a Core-unfolding narrative that doesn't match any real competitive build (Kennen), an analysis that omitted a real third Champion print entirely (Fiora, Shen, Vex -- the same pattern recurring three times), a "genuine partnership" where one side is essentially unplayed (Irelia's Graceful, Lee Sin's Ascetic), a win-condition claim stated as flatly false that real coverage directly inverts (LeBlanc), sources disagreeing with each other on the label even when the mechanic itself is confirmed (Mel, Renata Glasc), a "central engine card" claim inverted by real deckbuilding (Ornn), a genuinely near-even Champion split surviving the check for once (Sett's Brawler/Kingpin, unlike almost every other split claim checked), and -- most seriously -- a textually-accurate derivation describing a shell current top play doesn't build at all, because the real archetype uses cards entirely outside the Legend+Champion kit (Lux, Yasuo, Garen, Miss Fortune, Sivir). See each Legend's own row and `references/verification-log.md` for the specific finding and citations -- treat every entry's archetype call, "default Champion" assumption, and any "splits by Champion" claim as provisional until its own row says otherwise, not as settled just because the catalog is now fully checked.
