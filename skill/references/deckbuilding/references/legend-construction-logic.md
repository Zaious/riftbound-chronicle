# Legend construction logic (catalog index)

This file exists because the method demonstrated on Kai'Sa and Annie in the main deckbuilding book scales cleanly to the full roster -- the derivation is grounded in permanent card text and the game's own already-established archetype framework, not a community-guide snapshot, so it doesn't carry the staleness risk that would come from writing up 46 entries' worth of "what people currently play." Read the main book's methodology section first; this index plus the `legends/` files are the reference table it produces when run across the whole current roster, not a substitute for understanding the method itself.

**Every entry is a Tier 1 hypothesis, not a Tier 2-confirmed fact, unless the Status column says otherwise.** Every catalog entry checked against real established play so far has required a correction -- 3 for 3 (Darius, Master Yi, Viktor; see `references/verification-log.md`). Kai'Sa, one of the main book's two worked examples and not a row in this catalog, makes it 4 of 5 across the full verification log once she's included. Not a rare edge case either way. Specifically: (1) an entry's named archetype (aggro/control/combo) is this book's own framework, not guaranteed to match how the community actually talks about that Legend -- Darius and Kai'Sa's real-play labels don't fit the three-way split cleanly. (2) Any entry describing "the two Champions split into different lanes" is unverified by construction -- Tier 1 cannot tell a real fork from an apparent one, because that often depends on synergy with cards outside the Legend+Champion kit; Master Yi, Viktor, and Kai'Sa all read as forks on paper and were not, in practice. Treat every split-labeled entry below with that caveat until it's been through the verification log -- don't quote one as settled.

## How to use this table

1. **Looking up one Legend you already know the name of** -- find its row, open the linked file in `legends/`. That file has the full derivation; this row is only a summary.
2. **Looking for a counter-matchup, comparable archetype, or "which other Legend does something like this"** -- scan the Archetype and Mechanic tags columns first. They're deliberately kept as short, grep-able keywords for exactly this cross-referencing use case, so you don't have to open all 46 files to find candidates. Only open the specific files that look like real matches.
3. **Status** -- `Tier 1` (default, unverified hypothesis), `Tier 2 ✓` (confirmed or corrected against real play, see the linked file's callout and `verification-log.md`), or `Tier 1 (data caveat)` (Kennen only -- see note below).
