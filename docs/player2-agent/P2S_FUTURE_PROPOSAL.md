# P2-S Future Proposal — Not Implemented

Status: planned only
Implemented: no
Public runtime: excluded
Activation gate: written Riot approval and a separate maintainer decision

## Why this document exists

The long-term research direction may include structured TCG environments, imitation learning, self-play, or reinforcement learning. Recording that direction now prevents P2-A from being designed into a dead end. It does not authorize or begin implementation.

## Possible future capabilities

- Structured observation and action schemas.
- Hidden-information-safe recurrent policies.
- Legal-action masks generated by an authorized rules adapter.
- Replay buffers, imitation learning, and self-play.
- Checkpoint-versus-checkpoint evaluation.
- A game-agnostic TCG RL core with separately licensed game adapters.

## Prohibited in the current repository state

- Riftbound automated rule enforcement.
- Engine-owned game state.
- Automatic card-effect, combat, score, or win resolution.
- Public self-play or matchup result datasets.
- A standalone Riftbound digital game client.
- A code path that silently upgrades a P2-A session to P2-S.

## Required decision gates before implementation

1. Receive a written Riot determination covering the proposed user flow and distribution.
2. Decide whether the work belongs in this public repository, a generic multi-game repository, or an access-controlled adapter.
3. Document approved card/API/asset sources.
4. Reassess RSO, monetization, data-retention, and game-integrity requirements.
5. Add a separate threat model, evaluation policy, and release review.
6. Obtain explicit maintainer authorization to change `implemented: false`.

Until every gate is satisfied, P2-S remains architecture documentation only.
